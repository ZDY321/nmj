使用项目实际浏览器加密/缓存代码、Edge 独立上下文与合成档案。服务端 API 在测试中拦截；HTTP 上传探针仅在本地性能服务器接收字节并丢弃，不保存内容，也不发送到生产环境。时间为单次样本，不代表稳定网络吞吐。

上传探针确认收包字节等于请求字节。真实 Cloudflare/公网延迟没有测量，不能用本地时间替代。6000 课节样本证明当前 localStorage 配额会影响大档案；这一问题属于容量边界，不能靠拆文件消除。不同浏览器、其它缓存占用和历史数据大小都会改变边界。

40 学生/12 课程/240 课节的信任设备写入为 17ms、解密读取 9ms。验证本地保存为加密封装，密码和 token 不以明文出现在 localStorage；容量异常时退回 sessionStorage，关闭持久登录；清除后无法继续恢复。

六次快速编辑产生七次解锁会话缓存写入（每次输入及成功保存回写云端版本），每次 1–3ms，只产生一次云端上传。当前样本不支持为了减少这些写入而延迟本地恢复保障。本轮保留每次编辑的即时恢复缓存和 500ms 云端防抖。

已修复两条保存边界：旧 scheduleRules 清理等待云端恢复后进入保存队列，只提交一次正确版本；退出刷新在没有待防抖内容时也会等待已排队上传完成。已有版本冲突、强制覆盖确认、加密格式和信任设备语义不变。

决策：本轮不引入新文档类型或数据迁移，不改加密格式。IndexedDB 大档案缓存或云端文档分区需要兼容、离线、退出清理及失败恢复设计，应作为独立容量扩展工作评估。原计划阶段 7 的测量与架构评估已完成，容量限制明确保留。

原始结果：artifacts/performance/twentieth-batch-storage 与 twentieth-batch-upload。复现：npm run benchmark -- session-storage.spec.ts legacy-schedule-rules.spec.ts。
